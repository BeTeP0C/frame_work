# Система учета версий дизайн-макетов

## Назначение

Веб-приложение для хранения и учета версий дизайн-макетов. Приложение решает
проблему «final_final_v3.fig»: все версии макета хранятся в одном месте,
получают порядковый номер, автора, дату и комментарий, поэтому команда всегда
знает, какая версия актуальна, кто и что в ней изменил, и может вернуться к
любой предыдущей версии.

## Целевая аудитория

- дизайнеры, которые загружают новые версии макетов;
- ведущие дизайнеры и арт-директоры, которые проверяют и согласуют макеты;
- менеджеры проектов, которым нужно видеть историю изменений;
- разработчики, которым нужна актуальная версия макета для верстки.

## Предметная область

Дизайн-студии и продуктовые команды ведут несколько проектов (сайт, мобильное
приложение, бренд). В каждом проекте есть макеты — отдельные экраны или
страницы. Макет многократно дорабатывается, и каждая доработка сохраняется как
новая версия с файлом (.fig, .psd, .sketch), автором, датой загрузки и
описанием изменений. Загружать версии могут только участники проекта с ролью
дизайнера или ведущего дизайнера.

## Основные сущности

- **Проект** — название, описание, участники, дата создания;
- **Макет** — название, проект, к которому относится, номер актуальной версии;
- **Версия** — номер, файл макета, размер файла, дата загрузки, комментарий, автор;
- **Автор** — имя, роль в проекте (`lead`, `designer`, `viewer`).

## Основные функции

- проверка прав автора на загрузку версии (роль и участие в проекте) — *реализовано на ПР1*;
- проверка формата (.fig, .psd, .sketch) и размера файла макета — *реализовано на ПР1*;
- автоматическая нумерация новой версии макета — *реализовано на ПР1*;
- создание проектов и макетов;
- просмотр истории версий макета;
- откат к предыдущей версии и сравнение двух версий;
- согласование версии ведущим дизайнером.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

Проверка кода и тесты:

```bash
flake8 .
pytest
```

## Текущий сценарий (ПР1)

Загрузка новой версии макета: программа проверяет права автора, формат и размер
файла, присваивает версии следующий номер и выводит карточку версии. Если
проверка не пройдена, выводится причина отказа.

## План развития

На следующих этапах планируется:

- консольная программа с несколькими сценариями, функциями и модулями (ПР2);
- реализация сущностей в виде классов (ПР3);
- разработка веб-приложения на Django (ПР5–ПР6);
- подключение базы данных и моделей предметной области (ПР7–ПР9);
- формы загрузки версий и создания макетов (ПР10);
- реализация пользователей и разграничения доступа (ПР11);
- автоматизированные тесты (ПР13–ПР15);
- разработка API;
- контейнеризация приложения;
- настройка CI/CD.
