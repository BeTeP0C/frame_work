# Система учета версий дизайн-макетов

Консольное приложение для учета проектов, дизайн-макетов и истории их
версий.

## Назначение

Приложение решает проблему «final_final_v3.fig»: все версии макета хранятся
в одном месте, получают порядковый номер, автора, дату и комментарий,
поэтому команда всегда знает, какая версия актуальна, кто и что в ней
изменил, и может вернуться к любой предыдущей версии.

## Целевая аудитория

- дизайнеры, которые загружают новые версии макетов;
- ведущие дизайнеры и арт-директоры, которые проверяют и согласуют макеты;
- менеджеры проектов, которым нужно видеть историю изменений;
- разработчики, которым нужна актуальная версия макета для верстки.

## Предметная область

Дизайн-студии и продуктовые команды ведут несколько проектов (сайт,
мобильное приложение, бренд). В каждом проекте есть макеты — отдельные
экраны или страницы. Макет многократно дорабатывается, и каждая доработка
сохраняется как новая версия с файлом (.fig, .psd, .sketch), автором, датой
загрузки и описанием изменений. Загружать версии могут только участники
проекта с ролью дизайнера или ведущего дизайнера.

## Основные сущности

- **Проект** — идентификатор, название, описание;
- **Макет** — идентификатор, проект, название;
- **Версия** — идентификатор, макет, номер, файл, размер, автор, дата,
  комментарий;
- **Автор** — имя, роль (`lead`, `designer`, `viewer`), список проектов.

## Возможности

- просмотр макетов с номерами актуальных версий и количеством макетов
  в проектах;
- поиск макетов по части названия;
- просмотр истории версий макета;
- загрузка новой версии с проверкой прав автора, формата и размера файла;
- удаление версии;
- откат макета к старой версии;
- статистика по макету: число версий, число авторов, суммарный размер
  файлов, последний автор;
- справка по функциям проекта (интроспекция).

## Структура проекта

```
design-version-tracker/
├── main.py            — точка запуска, меню и вывод данных
├── projects.py        — работа с проектами
├── mockups.py         — работа с макетами
├── versions.py        — работа с версиями макетов
├── authors.py         — работа с авторами и ролями
├── storage.py         — загрузка и сохранение данных в JSON
├── utils.py           — ввод данных и вспомогательные функции
├── conftest.py        — настройка путей импорта для pytest
├── requirements.txt   — зависимости разработки
├── data/              — данные приложения
│   ├── projects.json
│   ├── mockups.json
│   ├── versions.json
│   └── authors.json
└── tests/             — автоматизированные тесты
    ├── test_mockups.py
    └── test_versions.py
```

## Формат хранения данных

Данные хранятся в JSON-файлах каталога `data/`: каждый файл содержит список
словарей. Чтение и запись выполняются в модуле `storage.py` через
контекстный менеджер `with`; отсутствие файла и некорректный JSON
обрабатываются исключениями `FileNotFoundError` и `json.JSONDecodeError`.

Пример записи версии из `data/versions.json`:

```json
{
  "id": 3,
  "mockup_id": 1,
  "number": 3,
  "file_name": "login_screen.fig",
  "size_mb": 12.5,
  "author": "Игорь Петров",
  "created_at": "2026-09-15",
  "comment": "Изменен цвет кнопки входа"
}
```

## Требования

- Python 3.x;
- pytest;
- flake8.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

## Запуск тестов

```bash
pytest
```

## Проверка качества кода

```bash
flake8 --exclude .venv .
```

## План развития

На следующих этапах планируется:

- реализация сущностей в виде классов (ПР3);
- разработка веб-приложения на Django (ПР5–ПР6);
- подключение базы данных и моделей предметной области (ПР7–ПР9);
- формы загрузки версий и создания макетов (ПР10);
- реализация пользователей и разграничения доступа (ПР11);
- расширение автоматизированных тестов (ПР13–ПР15);
- разработка API;
- контейнеризация приложения;
- настройка CI/CD.
