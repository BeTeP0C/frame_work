# Система учета версий дизайн-макетов

Консольное приложение для учета проектов, дизайн-макетов и истории их
версий. Предметная область представлена объектной моделью: проекты,
макеты, авторы и версии — это объекты классов.

## Назначение

Приложение решает проблему «final_final_v3.fig»: все версии макета хранятся
в одном месте, получают порядковый номер, автора, дату и комментарий,
поэтому команда всегда знает, какая версия актуальна, кто и что в ней
изменил, и может вернуться к любой предыдущей версии.

## Целевая аудитория

- дизайнеры, которые загружают новые версии макетов;
- ведущие дизайнеры и арт-директоры, которые проверяют и согласуют макеты;
- менеджеры проектов, которым нужно видеть историю изменений;
- разработчики, которым нужна актуальная версия макета для верстки.

## Предметная область

Дизайн-студии и продуктовые команды ведут несколько проектов (сайт,
мобильное приложение, бренд). В каждом проекте есть макеты — отдельные
экраны или страницы. Макет многократно дорабатывается, и каждая доработка
сохраняется как новая версия с файлом (.fig, .psd, .sketch), автором, датой
загрузки и описанием изменений. Загружать версии могут только участники
проекта с ролью дизайнера или ведущего дизайнера.

## Классы предметной области

| Класс | Атрибуты | Методы |
| --- | --- | --- |
| `Project` | `id`, `name`, `description` | `__str__()` |
| `Mockup` | `id`, `project`, `name` | `matches()`, `__str__()` |
| `Author` | `id`, `name`, `role`, `projects` | `role_title`, `can_upload_to()`, `__str__()` |
| `Version` | `id`, `mockup`, `number`, `file_name`, `size_mb`, `author`, `created_at`, `comment`, `is_archived` | `archive()`, `restore()`, `describe()`, `label`, `is_supported_format()`, `parse_size()`, `__str__()` |
| `RollbackVersion` | атрибуты `Version` и `source_number` | переопределяет `describe()` |

Особенности реализации:

- **композиция**: `Mockup` хранит объект `Project`, а `Version` — объекты
  `Mockup` и `Author`, поэтому данные связанных объектов доступны как
  `version.mockup.project.name` или `version.author.role_title`;
- **инкапсуляция**: признак архива хранится в `_is_archived` и доступен
  только для чтения через свойство `is_archived`; изменить состояние можно
  методами `archive()` и `restore()`;
- **наследование**: `RollbackVersion` — версия, созданная откатом; она
  наследует поведение `Version` и добавляет номер исходной версии;
- **полиморфизм**: история макета выводится одинаковым вызовом
  `version.describe()`, а версия-откат дополняет описание сведениями об
  источнике;
- **статические методы**: `Version.is_supported_format()` и
  `Version.parse_size()` относятся к классу, но не используют данные
  конкретного объекта.

## Взаимодействие объектов

```
Author ──создает──> Version ──относится к──> Mockup ──входит в──> Project
```

При загрузке новой версии функция `add_version()` проверяет права автора
(`author.can_upload_to()`), формат и размер файла, после чего создает объект
`Version`, связанный с объектами `Mockup` и `Author`.

## Возможности

- просмотр макетов с номерами актуальных версий и количеством макетов
  в проектах;
- поиск макетов по части названия;
- просмотр истории версий макета;
- загрузка новой версии с проверкой прав автора, формата и размера файла;
- перевод версии в архив без удаления из истории;
- откат макета к старой версии;
- статистика по макету: число версий, число архивных версий, число
  авторов, суммарный размер файлов, последний автор;
- просмотр авторов и их ролей;
- справка по классам и функциям проекта (интроспекция).

## Формат хранения данных

Данные хранятся в JSON-файлах каталога `data/`: каждый файл содержит список
словарей. В JSON записываются идентификаторы связанных объектов, а не сами
объекты: например, версия хранит `mockup_id` и `author_id`. При загрузке
`storage.py` находит нужные объекты `Mockup` и `Author` и передает их в
конструктор `Version`, а при сохранении выполняет обратное преобразование.
Чтение и запись выполняются через контекстный менеджер `with`; отсутствие
файла и некорректный JSON обрабатываются исключениями `FileNotFoundError`
и `json.JSONDecodeError`.

Пример записи версии из `data/versions.json`:

```json
{
  "id": 3,
  "mockup_id": 1,
  "number": 3,
  "file_name": "login_screen.fig",
  "size_mb": 12.5,
  "author_id": 2,
  "created_at": "2026-09-15",
  "comment": "Изменен цвет кнопки входа",
  "is_archived": false,
  "kind": "version"
}
```

Поле `kind` определяет, какой класс создается при загрузке: `version` —
`Version`, `rollback` — `RollbackVersion` (у такой записи есть еще поле
`source_number`).

## Требования

- Python 3.x;
- pytest;
- flake8.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

## Запуск тестов

```bash
pytest
```

## Проверка качества кода

```bash
flake8 --exclude .venv .
```
